Everything in the box

A whole writing surface, not just bold and italics

Saving, uploads and search stay in your app; the editor brings the rest.

A minimap you can actually follow

Not a shrunk photo of grey blocks, but a spatial outline. Headings render as readable labels at their true position, body text becomes content-derived density, images show real thumbnails, and the whole document fits the panel so you always know where you are. A collapsible document outline rides alongside it.

  • Click a heading to jump to it
  • Draggable viewport, fit to panel
  • Fully themeable via CSS variables

Focus mode & version history

Dim everything but the sentence you're writing for distraction-free drafting, with host-controlled column width, font and dimming. Keep a client-side history stack with a visual/text/source diff and one-click restore.

  • One active block, the rest recede
  • Diff view with restore
  • Records title, tags & categories, not just body

A toolbar your users can rearrange

Ship a settings gear that opens a drag-and-drop customizer: reorder tools, drop the ones you don't want, switch between main-toolbar and selection-menu layouts, or start from a preset like Blogger or Science / Academic. Scope the drawer to your editor panel or the whole viewport, your call.

  • Drag to reorder, presets to start fast
  • Separate main-toolbar & bubble-menu configs
  • Responsive: overflow collapses to “More”

How localization works, and how to change it in your app

The editor's own strings live under a dedicated inscript-editor i18next namespace and auto-register into your instance on mount, so it just works. Override or restrict languages explicitly:

import i18n from 'i18next';
import { registerInscriptEditorTranslations }
  from 'inscript-editor/locales';

registerInscriptEditorTranslations(i18n, {
  languages: ['en', 'de', 'fr'],   // register a subset
  overrides: { en: { insertImage: 'Add image' } },
});
i18n.changeLanguage('de');   // switch, live

No i18next at all? Every string carries an English default, so the editor still renders correctly. Full i18n docs →

Quick start

Two imports and a component

Own the editor instance with a hook; render it with one component. Everything else is props.

1. Install

# the package
npm install inscript-editor

# its peers (React + TipTap)
npm install react react-dom @tiptap/core \
  @tiptap/react @tiptap/starter-kit …

2. Use

import { useInscriptEditor, InscriptEditor }
  from 'inscript-editor';
import 'inscript-editor/styles';

function Post() {
  const api = useInscriptEditor({
    contentKey: filename,
    onContentChange: (e) => save(e),
  });
  return <InscriptEditor {...api} />;
}

Recipe: the outline & minimap in one sidebar

The DocumentOutline and MiniMap are separate exports, so compose them however you like. Here's the tabbed sidebar from the demo above, where only one is open at a time:

import { useState } from 'react';
import { DocumentOutline, MiniMap } from 'inscript-editor';

function EditorSidebar({ editor }) {
  const [tab, setTab] = useState('outline');
  return (
    <aside className="sidebar">
      <div className="tabs">
        <button onClick={() => setTab('outline')}>Outline</button>
        <button onClick={() => setTab('minimap')}>Minimap</button>
      </div>

      {tab === 'outline'
        ? <DocumentOutline editor={editor} />
        : <MiniMap editor={editor} />}
    </aside>
  );
}

Each component ships its own header and collapse control. To let your tab strip be the only header, hide theirs with one line of CSS:

/* the outline/minimap is the sidebar's last child; its header is that child's first child */
.sidebar > :last-child > :first-child { display: none; }
